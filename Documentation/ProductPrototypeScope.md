# GeoBeat 产品图交互原型范围

## 本轮目的

本轮把需求方提供的产品草图转换为可在 Xcode 中运行的 SwiftUI 交互原型，用来确认信息架构、页面层级、跳转关系、字段命名和主要操作，不作为正式数据版本。

原型默认使用示例数据。所有编辑、补录、计次和筛选只在本次 App 运行期间生效；重启 App 后恢复为初始示例数据。原型页面不读取或写入正式的 SwiftData 练习记录；只有用户从设置中主动进入原有正式功能后，才会使用现有正式数据。

## 已覆盖的页面与跳转

- 打卡首页：搜索、今日完成、全部曲目、曲目筛选、新建、归档入口、段落卡片。
- 曲目详情：总览、周/月/年示例统计，以及编辑、历史记录、补录入口。
- 曲目编辑：曲目名、分组、练习段落、目标、计数方式、归零周期和结束日期。
- 历史记录：按周/月/年/全部、日期范围和手型查看练习条目，并显示相邻记录间隔。
- 补录：时间、手型、BPM、训练音符、时长和次数。
- 进入练习：把曲目、段落、节拍参数和目标进度带入节拍器原型。
- 节拍器：播放状态、参数调整、手型切换、`x/n` 计次、结束结果预览和设置入口。
- 统计：周期、曲目、手型和排序筛选，示例时间线，以及 GEOBEAT BILL 分享预览。
- 设置：默认节拍参数、提醒、外观、触感、数据和关于入口。

## 本轮刻意不实现的内容

- 不把 Mock 记录接入正式 `PracticeAttempt` / `PracticeEvent` 数据。
- 不确定日、周、月、年统计最终计算口径，不做数据库迁移或历史回填。
- 不接入真实提醒通知、iCloud、备份恢复、订阅或 StoreKit。
- 不把账单预览保存为正式图片或 PDF。
- 不把原型节拍器的计次写入正式练习报告。

## 为提升确认效率而顺手实现的轻量逻辑

- 页面内搜索、筛选和路由。
- Mock 曲目编辑、新建段落、补录和计次的内存联动。
- BPM、拍数、音符、手型和目标进度的本地交互。
- 统计页基于 Mock 记录的简单筛选与汇总，仅用于验证展示结构。
- 系统分享面板分享示例账单文本。

## 待需求方确认后再接真实数据的关键问题

- “曲目”和“练习段落”的最终层级、命名与归档规则。
- `x/n` 中的目标是每日目标、当前周期目标，还是曲目总目标。
- 一条历史记录应对应一次完整练习、一次 `+1`，还是手型/速度变化后的分段。
- 统计中的“练习次数”“练习天数”“练习度”和间隔时间的最终定义。
- 补录是否允许修改既有记录，以及修改后如何影响目标与统计。
- 分享账单的周期、字段、视觉规格和导出格式。
- PRO 功能范围及未订阅状态下的降级交互。

## 原型入口

- Debug 构建默认进入产品原型，原型设置页提供“查看当前正式功能”的返回通道；该入口是原有正式界面，并继续使用现有数据。
- 带 `CUSTOMER_PREVIEW` 的 Release/TestFlight 构建进入产品原型。
- 不带 `CUSTOMER_PREVIEW` 的正式 Release 构建仍进入原有 `RootView`。
